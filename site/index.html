The set

Five skills, one standard.

Each is a self-contained SKILL.md plus whatever it needs to run. Written for agents — trigger, steps, verification, pitfalls.

Output

token-lean-answers

skills/token-lean-answers

Maximum meaning per token. Cut what carries nothing, keep what prevents a re-ask — and never drop the caveat that changed a decision.

Research

short-form-performance-standards

skills/short-form-performance-standards

2026 benchmarks for Reels, Shorts and TikTok: hook windows, length bands, cadence, and which metrics actually decide. Every figure dated and sourced.

Video

html-to-video-local

skills/html-to-video-local

Render HTML/CSS to video offline and deterministically — local Chromium and ffmpeg, with byte-identical re-renders and a lint that proves it.

Inspection

web-app-teardown

skills/web-app-teardown

Find out what a live web app actually runs — shipped bundle plus a DevTools capture — instead of trusting its marketing pages.

Tooling

installing-third-party-repos

skills/installing-third-party-repos

Install a repo properly: triage its shape, mirror linked layouts, audit it for telemetry, and verify with a real check rather than an exit code.

Principles

What these have in common.

Verify with a real check
An exit code proves nothing — probe the artifact and say what came back.
Measure before claiming
Figures carry a date and a source. Anything thin is labelled reported, not measured.
Report what is unknown
A skill that hides its gaps is worse than no skill at all.
No telemetry
Nothing dials out. Where an upstream source did, those parts were removed.
No personal data
Enforced by an automated gate that runs on every push and pull request.

Install

Copy one folder.

Skills are plain Markdown. Any agent that reads a skills directory can use them — no build step, no account, no service.

$ git clone https://github.com/raihanhaqueofficial/agent-skills

# copy one skill into your agent's skills root
$ cp -r agent-skills/skills/token-lean-answers ~/.your-agent/skills/

# verify compliance before you fork or contribute
$ ./scripts/compliance-check.sh

Compliance

Documented, not assumed.

A licence is not a trademark, and a privacy policy is not boilerplate. Each of these says a true thing about what the project does.

LICENSE · MIT TRADEMARK.md PRIVACY.md · collects nothing DISCLAIMER.md SECURITY.md CONTRIBUTING.md CODE_OF_CONDUCT.md CHANGELOG.md CI compliance gate

No separate Terms & Conditions, deliberately. MIT is the terms — restrictive terms on top would contradict the licence. What a licence cannot grant is rights to a name, so that document exists instead.

FAQ

Short answers.

What is this?

A small, opinionated set of skills for AI coding agents, built while doing real video, research and tooling work. Written to be portable and verifiable, not clever.

Is it free?

Yes — MIT. Use it, modify it, ship it commercially.

Does anything phone home?

No. No network calls to my servers, no analytics, no accounts, no cookies from this project. Where an upstream tool reported usage, those components were removed and the change recorded.

Why no Terms & Conditions file?

Because MIT already is the terms. A restrictive T&C over a permissive licence creates a contradiction. The trademark policy covers what a licence genuinely cannot.

Can I contribute?

Yes. Two rules: no personal data, no telemetry. Run ./scripts/compliance-check.sh before you push — it is the same gate CI runs.
